- `collect.sh` — copy the machine-side files of the fleet into this project: the resource guard, systemd units, agent lists (banned name swapped for its stand-in, `config/` only), terminal config, the tmux patch, and the fleet's keys from Claude's and Gemini's settings. The fleet's own programs and tmux config already live here (home paths are links), so they are counted as "already live", not copied. Never copies sign-ins or chats. `bash _tools/collect.sh [--dry-run]`. Exits non-zero if a listed file is missing.
- `install.sh` — set a machine up to run the fleet from this folder: links the home paths of the programs, library, tmux config and launcher files to the files here, and copies the guard, units and lists as real files. Dry run by default; `--apply` does it and keeps anything it replaces as `<file>.bak-<date>`; `--apply --copy` makes real copies instead of links. Does not sign in, edit agent settings, build tmux or restart anything; it prints those steps. `bash _tools/install.sh [--apply] [--copy]`.
- `test-fleet.sh` — try the launcher on a throw-away fleet before trusting it with the real one: its own tmux server, its own home folder under `/tmp`, and stand-ins for the four agents, `notify-send` and the usage tools, so nothing real is started, asked or shown. About 80 checks in three minutes: the saved layout and a restart that gives it all back, a fleet going down hard, notifications, the limit warning, the overview, tab signals, work folders, handing a chat on, `--doctor`. `bash _tools/test-fleet.sh [--bin DIR] [--conf FILE] [--keep]`. Exits 1 if a check fails. Run it after any change to `bin/agents`.
- `test-rules.sh` — try the rule check (`bin/afc-rules`) on a made-up TokenOps project with hand-written chat files of Claude, Codex and Gemini and a stand-in home folder, all under one temp folder: 36 checks in a few seconds. What sends an agent back and what only notes, once per turn, the reminder of each tool, where it does nothing (no TokenOps files, another git repo inside), broken input, and that `afc-rules install` adds and `--remove` takes out exactly its hooks without breaking the accounts' links. `bash _tools/test-rules.sh [--rules FILE] [--keep]`. Run it after any change to `bin/afc-rules` or to the chat readers in `bin/afc-logs`.
- `server-setup.sh` — set a newly installed Ubuntu server (no desktop) up to run the fleet, in one go, over SSH: apt packages, Claude Code, `install.sh --apply`, `agents.slice` sized for that machine (all cores but one, slowed at 75% of memory, stopped at 85%), the patched tmux, Claude's settings, linger and the background services. Skips what is already done; leaves sign-ins, the other agents and the keep-screen-awake service alone. Tried end to end on fresh Ubuntu 24.04 and 26.04. `bash _tools/server-setup.sh [--dry-run] [--copy]`.
- `windows-setup.sh` — set Windows up to run the fleet, run inside WSL (Start > Ubuntu). tmux is not a Windows program, so the fleet runs in WSL2, which is real Linux on the same PC: this checks WSL itself (turns systemd on in `/etc/wsl.conf` and tells you the `wsl --shutdown` only Windows can run), hands the whole Linux half to `server-setup.sh`, and adds a "Fleet" profile to Windows Terminal. What Windows adds over a headless server: sign-in opens the real browser, the clipboard is shared both ways, notifications are Windows toasts, Alt+N is Windows' folder dialog. What it skips: keep-awake, and a toast has no "Open the tab" button. `bash _tools/windows-setup.sh [--dry-run] [--copy]`.
- `test-wsl.sh` — check the Windows side from Linux: it pretends to be WSL and stands in for `powershell.exe`, `wt.exe`, `cmd.exe`, `wslpath` and `clip.exe`, then reads back what the fleet asked Windows to do. 15 checks in under a minute: finding Windows, the clipboard both ways, a path with a quote in it reaching PowerShell safely, the toast, the Agents window, and what `--doctor` says when interop is off. This proves the plumbing in `bin/agents`, not that Windows behaves as expected — only a real PC does that. `ACF_REPO=<this folder> bash _tools/test-wsl.sh`.
- `mac-setup.sh` — set a Mac up to run the fleet, in one go, run on the Mac itself: Homebrew packages (bash 5, GNU coreutils/sed/awk/grep/findutils, flock, the tmux build's libraries), `install.sh --apply`, the patched tmux, Claude's settings, the chat log as a launchd job every 15 minutes, and `~/.local/bin` on the PATH. Skips what is already done; leaves sign-ins and the agents alone. A Mac has no resource budget, no keep-awake and no desktop notifications (Linux's cgroups, systemd and `notify-send`), and no plan limits in the pane headers, because Claude keeps its sign-in in the Keychain there. Written for the Mac's own bash 3.2, since it runs before Homebrew's bash is there. `bash _tools/mac-setup.sh [--dry-run] [--copy]`.
- `build-tmux.sh` — build the fleet's patched tmux 3.8 from this folder alone: `tmux/src/tmux-3.8.tar.gz` + `tmux/afc-tmux-3.8.patch` + the build packages in `tmux/deps/` (checked against `tmux/SHA256SUMS`). No download, no sudo, about a minute. Installs to `~/.local/opt/tmux-3.8` and keeps the previous program as `bin/tmux-before-<date>`. `bash _tools/build-tmux.sh [--prefix DIR] [--dry-run] [--system-deps]`. `--system-deps` builds against the machine's own libevent, ncurses and bison instead of `tmux/deps/` (those are for Ubuntu 24.04 on amd64). Does not restart the fleet.
