- `collect.sh` — copy the machine-side files of the fleet into this project: the resource guard, systemd units, agent lists (banned name swapped for its stand-in, `config/` only), terminal config, the tmux patch, and the fleet's keys from Claude's and Gemini's settings. The fleet's own programs and tmux config already live here (home paths are links), so they are counted as "already live", not copied. Never copies sign-ins or chats. `bash _tools/collect.sh [--dry-run]`. Exits non-zero if a listed file is missing.
- `install.sh` — set a machine up to run the fleet from this folder: links the home paths of the programs, library, tmux config and launcher files to the files here, and copies the guard, units and lists as real files. Dry run by default; `--apply` does it and keeps anything it replaces as `<file>.bak-<date>`; `--apply --copy` makes real copies instead of links. Does not sign in, edit agent settings, build tmux or restart anything; it prints those steps. `bash _tools/install.sh [--apply] [--copy]`.
- `test-fleet.sh` — try the launcher on a throw-away fleet before trusting it with the real one: its own tmux server, its own home folder under `/tmp`, and stand-ins for the four agents, `notify-send` and the usage tools, so nothing real is started, asked or shown. About 90 checks in three minutes: the saved layout and a restart that gives it all back, a fleet going down hard, notifications, the limit warning, the overview, tab signals, work folders, handing a chat on, `--doctor`. `bash _tools/test-fleet.sh [--bin DIR] [--conf FILE] [--keep]`. Exits 1 if a check fails. Run it after any change to `bin/agents`.
- `test-rules.sh` — try the rule check (`bin/afc-rules`) on a made-up TokenOps project with hand-written chat files of Claude, Codex and Gemini and a stand-in home folder, all under one temp folder: 42 checks in a few seconds. What sends an agent back and what only notes, once per turn, the reminder of each tool, where it does nothing (no TokenOps files, another git repo inside), broken input, moving Claude's memory into the project, and that `afc-rules install` adds and `--remove` takes out exactly its hooks without breaking the accounts' links. `bash _tools/test-rules.sh [--rules FILE] [--keep]`. Run it after any change to `bin/afc-rules` or to the chat readers in `bin/afc-logs`.
- `test-idle.sh` — try the idle stop of `bin/autonice` (`idle <class> <time>` in the rules): a second autonice with its own rules and state under one temp folder, watching only made-up servers no real rule matches, and sending no notification. 16 checks in about two minutes: an idle server is stopped and a working one is not, a terminal-started one counts, no rule or an unreadable time stops nothing, and a server the gate holds paused is not counted as idle. `--autonice FILE` tests another copy (the live one is `~/.local/bin/autonice`).
- `test-single.sh` — try the duplicate stop of `bin/autonice` (`single <class> <time> [port]` in the rules), the same way as `test-idle.sh`: its own autonice, rules and state under one temp folder, made-up servers only, no notification. 35 checks in about two minutes: a second server in a folder is stopped and the first stays, whatever port it asks for; the log and the stopped one's own output say why; another folder is another project; with `port` on the rule a server on a port of its own is allowed (`-p`, `--port=`, `PORT=`); a restart is let through; a copy whose output nobody reads cannot hang the watcher; one the gate holds paused is stopped too, a terminal-started one too; no rule or an unreadable time stops nothing. `--autonice FILE` tests another copy.
- `test-turn.sh` — try the turn stop of `bin/autonice` (`turn <class> <time>` in the rules: an agent's dev server is stopped when that agent's reply ends). Its own autonice, a tmux server of its own on its own socket with three made-up panes whose marks the test sets by hand, and made-up servers carrying the environment an agent's would. 26 checks in about two minutes: the server stays while its agent works and goes when the reply ends (also a reply that ended with a background shell, and a closed agent); waiting for permission or a new prompt keeps it; a server typed in the pane, one from outside tmux and one from a plain terminal are never touched; another agent at work in the same folder keeps it, one in another project does not; a closed pane or a gone fleet ends it; nothing is stopped when tmux cannot be asked, with no rule, or with an unreadable time. `--autonice FILE` tests another copy. Run all three (`test-idle.sh`, `test-single.sh`, `test-turn.sh`) after any change to `bin/autonice`, one after another: side by side, each one's autonice sees the others' made-up servers and they fail.
- `test-copy.sh` — try the clean copy (`bin/afc-copy`, the fleet's tmux `copy-command`): the filter runs with `--print`, so the clipboard is never written. 22 checks in a few seconds: a quoted paragraph from a narrow pane comes out as one line of plain text (also picked up from mid-line), an empty quote line stays a paragraph break, a reply and tool output lose their marks and margin; short lines of code, list items, tables and blank lines are never joined; a long address the pane cut is joined without a space; wide characters; `--raw`; the clipboard command it is given; and two real tmux copies on a server of its own, one the way the mouse bindings call it (`copy-pipe-and-cancel -C`) and one as the plain `copy-command`. `--copy FILE` tests another copy. Run it after any change to `bin/afc-copy` or to the copy lines of `tmux/tmux.conf`.

- `test-even.sh` — try the even-out of splits (`bin/afc-even`, used after a split, close, minimise or restore instead of tmux 3.8's `select-layout -E`, which pushed a top/bottom stack past the tab's edge) and its guard (no split left out of sight). A tmux server of its own with a client of its own, 118 columns wide (where the fault showed) and later 40, panes that only sleep. 45 checks in about 25 seconds: three columns share evenly; splitting the right one below keeps the stack on screen, in halves, then thirds; a split to the right counts the stack as one column; what `--gone` names before a close, and closing then evening; the real keys pressed in the client (Alt+\, Alt+-, Alt+Q yes, no and minimise-instead, also on a tab's only split, Alt+H, Alt+U) with every pane still inside the tab; that tmux's own `-E` still breaks a tab here and `--fix` repairs it evenly with the panes in their places; the guard by itself: a broken tab shared out again with nothing minimised, a border dragged over a split (it is minimised, the widened one keeps its width), the window shrunk to 40 columns (the splits without room minimised, the one you are in kept), and no guard left running. Run it after any change to `bin/afc-even`, `bin/afc-min`, `bin/afc-reflow`, the split and close parts of `bin/agents`, or the split and close keys in `tmux/tmux.conf`.
- `server-setup.sh` — set a newly installed Ubuntu server (no desktop) up to run the fleet, in one go, over SSH: apt packages, Claude Code, `install.sh --apply`, `agents.slice` sized for that machine (all cores but one, slowed at 75% of memory, stopped at 85%), the patched tmux, Claude's settings, linger and the background services. Skips what is already done; leaves sign-ins, the other agents and the keep-screen-awake service alone. Tried end to end on fresh Ubuntu 24.04 and 26.04. `bash _tools/server-setup.sh [--dry-run] [--copy]`.
- `windows-setup.sh` — set Windows up to run the fleet, run inside WSL (Start > Ubuntu). tmux is not a Windows program, so the fleet runs in WSL2, which is real Linux on the same PC: this checks WSL itself (turns systemd on in `/etc/wsl.conf` and tells you the `wsl --shutdown` only Windows can run), hands the whole Linux half to `server-setup.sh`, and adds a "Fleet" profile to Windows Terminal. What Windows adds over a headless server: sign-in opens the real browser, the clipboard is shared both ways, notifications are Windows toasts, Alt+N is Windows' folder dialog. What it skips: keep-awake, and a toast has no "Open the tab" button. `bash _tools/windows-setup.sh [--dry-run] [--copy]`.
- `test-wsl.sh` — check the Windows side from Linux: it pretends to be WSL and stands in for `powershell.exe`, `wt.exe`, `cmd.exe`, `wslpath` and `clip.exe`, then reads back what the fleet asked Windows to do. 22 checks in under a minute: finding Windows, the clipboard both ways, a path with a quote in it reaching PowerShell safely, the toast, the Agents window, the clean copy going to `clip.exe` (not WSLg's xclip; plain ASCII as it is, anything else as UTF-16 behind a byte-order mark), the machine wall holding with no `agents.slice` to read, and what `--doctor` says when interop is off. This proves the plumbing in `bin/agents`, not that Windows behaves as expected — only a real PC does that. `ACF_REPO=<this folder> bash _tools/test-wsl.sh`.
- `mac-setup.sh` — set a Mac up to run the fleet, in one go, run on the Mac itself: Homebrew packages (bash 5, GNU coreutils/sed/awk/grep/findutils, flock, the tmux build's libraries), `install.sh --apply`, the patched tmux, Claude's settings, the chat log as a launchd job every 15 minutes, and `~/.local/bin` on the PATH. Skips what is already done; leaves sign-ins and the agents alone. A Mac has no resource budget, no keep-awake and no desktop notifications (Linux's cgroups, systemd and `notify-send`), and no plan limits in the pane headers, because Claude keeps its sign-in in the Keychain there. Written for the Mac's own bash 3.2, since it runs before Homebrew's bash is there. `bash _tools/mac-setup.sh [--dry-run] [--copy]`.
- `build-logo.py` — make the logo files from `logo.png` (an animated PNG, 61 frames): the icon in nine sizes on a white rounded tile (`share/icons/hicolor/*/apps/acf.png`), `share/acf/acf.ico` for Windows Terminal, and the splash's frames (`share/acf/splash.png` + `splash.json`, played by `bin/afc-splash`). Needs Pillow; the results are committed. `python3 _tools/build-logo.py [--check]`.
- `build-deb.sh` — make the installer: `dist/agentic-cli-fleet_<VERSION>_amd64.deb` for an Ubuntu desktop. The fleet in `/opt/agentic-cli-fleet` with its tmux built for it, the Agents app-menu entry and the logo, software-centre metadata. The lists go in as templates; the build stops if one of this machine's paths is left in. Staged on ext4 (`~/.cache/acf-deb`); installs nothing. `bash _tools/build-deb.sh [--dry-run] [--no-tmux]`.
- `first-run.sh` — what the `.deb` runs the first time a user opens Agents (in a terminal window, with the splash): points `~/.local/opt/tmux-3.8` at the package's tmux, runs `server-setup.sh` (linger left off, so no sudo), turns keep-awake on, then opens the fleet. `bash /opt/agentic-cli-fleet/_tools/first-run.sh [--dry-run]`.
- `build-tmux.sh` — build the fleet's patched tmux 3.8 from this folder alone: `tmux/src/tmux-3.8.tar.gz` + `tmux/afc-tmux-3.8.patch` + the build packages in `tmux/deps/` (checked against `tmux/SHA256SUMS`). No download, no sudo, about a minute. Installs to `~/.local/opt/tmux-3.8` and keeps the previous program as `bin/tmux-before-<date>`. `bash _tools/build-tmux.sh [--prefix DIR] [--dry-run] [--system-deps]`. `--system-deps` builds against the machine's own libevent, ncurses and bison instead of `tmux/deps/` (those are for Ubuntu 24.04 on amd64). Does not restart the fleet.
